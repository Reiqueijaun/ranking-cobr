COLOCAR O RANKING NO AR

Este guia é pra quem vai publicar o site. Isso precisa de um computador uma vez só. Depois de publicado, o dono do clã faz tudo pelo celular: registra as massas, anexa os prints e apaga erros. No fim do guia tem uma mensagem pronta pra mandar pra ele.

  • Computador (só pra publicar)
  • Conta no GitHub
  • Uns 20 minutos
  • Custo: R$ 0
1

Abra a pasta e veja o site

2 MINUTOS

  1. Se recebeu um arquivo .zip, clique nele com o botão direito e escolha Extrair tudo.
  2. Dentro da pasta, dê dois cliques no index.html. O site abre no navegador em modo demonstração, com dados de exemplo.
  3. Lá embaixo, em Área do admin, entre com qualquer e-mail e a senha 1234 pra ver como registrar. Nesse modo nada é salvo, é só pra testar.
2

Conta no GitHub

PULE SE JÁ TIVER

O GitHub guarda os arquivos do site. Com essa conta você também entra no Supabase e na Vercel, sem criar outra senha.

  1. Entre em github.com/signup e crie a conta (e-mail, senha e um nome de usuário).
  2. Confirme o código que chega no seu e-mail.
3

Crie o banco de dados no Supabase

8 MINUTOS

  1. Entre em supabase.com/dashboard e clique em Continue with GitHub.
  2. Clique em New project. Nome: ranking-cobr. Region: South America (São Paulo). Crie uma senha do banco (anote em algum lugar, mas o site não usa). Clique em Create new project e espere uns 2 minutos.
  3. No menu da esquerda, clique em SQL Editor.
  4. Na pasta do site, abra o arquivo supabase-setup.sql com o Bloco de Notas (botão direito → Abrir com). Aperte Ctrl+A, depois Ctrl+C.
  5. Volte no Supabase, clique na área de texto, aperte Ctrl+V e clique em Run. Tem que aparecer Success. No rows returned.

Agora crie a conta de admin. Cada admin (dono, vice…) tem o próprio e-mail e senha. Ninguém mais consegue registrar ou apagar.

  1. No menu da esquerda, vá em Authentication → Sign In / Providers e deixe ligados Allow new users to sign up e Confirm email. Clique em Save changes. Os jogadores criam a conta deles pelo site (só serve pro "Meu perfil": admin é só quem está na tabela admins).
  2. Vá em Authentication → URL Configuration e coloque o endereço do site em Site URL. É pra lá que o link de confirmação do e-mail leva.
  3. Vá em Authentication → Users, clique em Add user → Create new user. Coloque o e-mail e uma senha forte, deixe marcado Auto Confirm User e clique em Create user.
  4. Volte no SQL Editor, apague tudo, cole a linha abaixo trocando o nome e o e-mail, e clique em Run:
insert into public.admins (user_id, nome)
select id, 'Seu nome' from auth.users where email = 'seu@email.com'
on conflict (user_id) do update set nome = excluded.nome;
Tem que aparecer Success. 1 rows affected. Se aparecer 0 rows, o e-mail não bate com o do usuário criado.
Pra ter mais de um admin, repita os passos 3 e 4 pra cada pessoa. Cada um usa a própria senha: não compartilhe a sua.

Por último, pegue os dois códigos do seu banco. Clique em Connect no topo da página (ou vá em Project Settings → API Keys) e deixe aberto. Você vai precisar de:

  • Project URL: algo como https://abcdxyz.supabase.co
  • A chave anon public ou publishable: um código comprido
Nunca use a chave service_role nem a secret. Essas abrem o banco inteiro.
4

Suba os arquivos no GitHub

5 MINUTOS

  1. Em github.com/new, em Repository name escreva ranking-cobr. Deixe Public e clique em Create repository.
  2. Na página que abrir, clique no link uploading an existing file.
  3. Abra a pasta do site, selecione todos os arquivos (Ctrl+A) e arraste pra página do GitHub.
  4. Espere carregar e clique em Commit changes.
5

Ligue o site no banco

3 MINUTOS

  1. No GitHub, dentro do ranking-cobr, clique no arquivo config.js.
  2. Clique no lápis (Edit this file), no canto direito.
  3. Troque COLE_AQUI_A_PROJECT_URL pela Project URL do Supabase. Troque COLE_AQUI_A_CHAVE_ANON_OU_PUBLISHABLE pela chave anon/publishable. Deixe as aspas. Fica assim:
SUPABASE_URL: "https://abcdxyz.supabase.co",
SUPABASE_KEY: "eyJhbGciOiJIUzI1NiIs...",
  1. Clique em Commit changes… e depois em Commit changes de novo.
Essa chave pode ficar visível no GitHub, ela foi feita pra isso. O banco só deixa visitante ver o ranking. Registrar e apagar só funciona pra quem entra com uma conta de admin.
6

Publique na Vercel

3 MINUTOS

  1. Entre em vercel.com/signup, escolha Hobby e clique em Continue with GitHub.
  2. Clique em Add New… → Project.
  3. Ache o ranking-cobr na lista e clique em Import. Se ele não aparecer, clique em Adjust GitHub App Permissions e libere o repositório.
  4. Não mude nada e clique em Deploy.
  5. Em menos de um minuto aparece a tela de parabéns. Clique em Continue to Dashboard. O link do site fica em Domains, algo como ranking-cobr.vercel.app.

MUDAR ALGUMA COISA

Tudo que dá pra mudar fica no config.js. No GitHub: clique no arquivo, depois no lápis, mude e clique em Commit changes. Em 1 minuto o site atualiza sozinho.

  • Quanto vale cada partida: mude os números em PONTOS.
  • Abrir o ranking por maior massa em vez de pontos: troque RANKING_POR: "pontos" por "massa".
  • Exigir print pra registrar: troque PRINT_OBRIGATORIO: false por true.
  • Trocar a logo: suba outra imagem com o nome logo-cobr.webp (Add file → Upload files).
  • Nomes e pontos das patentes: mude em PATENTES.
  • Trocar a senha de um admin: no Supabase, em Authentication → Users, clique nos 3 pontinhos do usuário e escolha Send password recovery (ou apague e crie de novo, repetindo o passo 3).
  • Tirar o acesso de um admin: em Authentication → Users, apague o usuário. Ele perde o acesso na hora.
  • Ver quem fez o quê: em Table Editor → admin_log fica registrado cada registro, edição e exclusão, com o e-mail de quem fez.
  • Corrigir um nick escrito errado: na Área do admin, em Jogadores do clã, toque no lápis do jogador e troque o nick. As partidas dele mudam junto.
  • Torneios: tudo pelo site, na Área do admin: Criar torneio, Editar, Encerrar agora, Publicar (rascunho só admin vê) e Apagar (dentro de Editar). Não precisa mexer em código.
  • Nomes dos cargos: por padrão são Líder, Vice-líder e Membro. Pra mudar, adicione no config.js uma linha como CARGOS: ["Líder", "Vice-líder", "Elite", "Membro"], (o primeiro é o mais alto).

ATUALIZAR UM SITE QUE JÁ ESTÁ NO AR

Pra quem já tinha o site no ar (inclusive a versão antiga com PIN):

  1. No Supabase, abra o SQL Editor, cole o supabase-setup.sql novo inteiro e clique em Run. Não apaga partidas nem jogadores. O PIN antigo deixa de existir.
  2. Crie a conta de admin (passo 3, a parte “Agora crie a conta de admin”).
  3. No GitHub, clique em Add file → Upload files e suba só index.html, app.js e style.css. Clique em Commit changes.
Não suba o config.js desta pasta. O do GitHub já tem os seus códigos do Supabase; o desta pasta está em branco e deixaria o site em modo demonstração.

SE DER PROBLEMA

  • Aparece "Modo demonstração" no site publicado: o config.js não foi salvo com os códigos. Refaça o passo 5.
  • "Não consegui ler o ranking": um dos códigos do config.js está errado (confira se não sobrou espaço ou faltou aspas), ou o script do passo 3 não rodou.
  • "E-mail ou senha errados": confira o e-mail em Authentication → Users. Se esqueceu a senha, veja “Trocar a senha de um admin” acima.
  • "Essa conta não tem acesso de admin": a conta existe, mas falta a linha do insert into public.admins do passo 3.
  • "Muitas tentativas": o Supabase bloqueia por alguns minutos quem erra a senha muitas vezes. É proteção, espere e tente de novo.
  • A seção de torneios não aparece, ou o admin vê "Os torneios ainda não foram ligados no banco": rode o supabase-setup.sql inteiro de novo no SQL Editor. Ele cria as tabelas dos torneios sem apagar nada.
  • Erro ao enviar com print: rode de novo o supabase-setup.sql inteiro. Pode rodar quantas vezes quiser, ele não apaga nada.
  • O site parou depois de muitos dias sem uso: no plano grátis, o Supabase pausa o banco depois de uma semana sem nenhum acesso. Entre no Supabase e clique em Restore project. Com o clã usando, isso não acontece.
